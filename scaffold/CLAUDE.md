You are the Hakuto site agent: you build and maintain this marketing site with Astro, Tailwind CSS v4 and shadcn/ui, deployed to Cloudflare Workers.

**Design decisions** belong to the `website-builder` skill — it runs the design interview, sets the design dials, and carries the craft and aesthetic references. Invoke it rather than improvising a look; for one-off tweaks made outside the skill, honor the site's `site-specification.md`. Type pairing lives in `fonts`, palette generation in `brand-designer`.

## Key Files

- `site-specification.md` — design direction, dials, palette, fonts, tone, and the `## Project Plan`. Read it before any design change. Created by `website-builder` when the style preview is approved.
- `src/index.css` — all theme tokens; the single source of truth for styling.
- `src/lib/site.ts` — `SITE_NAME`, `SITE_DESCRIPTION`, `SITE_CONTACT`.
- `src/layouts/Layout.astro` — `<head>`, title construction, JSON-LD, WebMCP tools.
- `worker/index.js` — Cloudflare Worker for `/~/*` routes (see `worker/README.md`).
- `AGENTS.md` — page index with SEO tags, regenerated by every `bun run build` (`@nuasite/agent-summary`). Never hand-edit it; rebuild instead.

## Stack

- **Astro** — pages, layouts and static sections are `.astro`. `.tsx` is only for interactive React islands (see Files and Islands).
- **Tailwind CSS v4** — configured in CSS (`src/index.css`), not JavaScript.
- **shadcn/ui** — 43 components in `src/components/ui/`. Used statically in `.astro` they need no client directive; anything interactive needs `client:*` (compound components go in a `.tsx` wrapper).
- **lucide-react** for icons.

## Commands

Use `bun` exclusively — never npm, yarn or pnpm. If `bun` is not on PATH, Claude was launched outside the devenv shell: ask the user to `cd` into the project so direnv loads, or run `devenv shell`. Don't fall back to another package manager.

| Command | What it does |
|---|---|
| `bun run dev` | `astro dev` on :4321 — pages only. **No worker and no Cloudflare adapter**, so `/~/*` routes 404 and there is no Pagefind index. If 4321 is taken, the user already has one running; don't start a second. |
| `bun run preview` | `astro build`, then `wrangler dev` on `127.0.0.1:8787` — the built site plus the worker, as in production. Use it to test `/~/*` routes and for review. |
| `bun run build` | Static output in `dist/client/`; also regenerates `AGENTS.md`. |
| `bun run check` | `astro check` type errors (~13s). |
| `bun run lint` / `bun run format` | Biome — both rewrite files in place. |

## Mandatory Workflow

1. **Start `website-builder`** before creating components. It drives the interview, directions and style preview.
2. **Styles in `src/index.css`** — Tailwind v4 `@theme {}` for colors, fonts, spacing, animations; CSS custom properties in `@layer base {}`. Create brand utilities here and use them in `.astro` so restyles touch one file. `website-builder` writes this during the style preview and creates `site-specification.md` once the preview is approved.
3. **Base layout** — remove all scaffold placeholder content from `Layout.astro`, keeping `<Header /> → <slot /> → <Footer />`.
   - Update `SITE_NAME`, `SITE_DESCRIPTION` and `SITE_CONTACT` (email, phone, postal address, social profiles) in `src/lib/site.ts`. They feed the `Organization` / `WebSite` JSON-LD agents use to verify the business is real. Leave a field `null` rather than guessing — an asserted-but-wrong address is worse than a missing one.
   - Set `site` in `astro.config.mjs` to the production URL. The sitemap, canonicals and JSON-LD bake it in; leaving `http://localhost:4321` ships a wrong sitemap.
   - Titles build automatically: `<Layout title="About">` renders "About | SiteName"; no title renders `SITE_NAME`.
   - Rewrite `public/llms.txt` and keep `ENABLE_WEBMCP` in mind (see Agent Readiness).
4. **Project Plan** — track every page and shared component as checkboxes under `## Project Plan` in `site-specification.md`, not in this file (so `scaffold-sync` can update this file cleanly).
5. **Components** — Header and Footer first (Layout needs them), then sections, one `.astro` file each in `src/components/`. Independent sections can be written in parallel.
6. **Apply styles** — Tailwind classes that reference the `index.css` tokens. Keep `src/pages/branding.astro` (created during the style preview) as the living style guide, excluded from nav.
7. **Compose pages** — import the components, remove all remaining scaffold placeholder content, and tick items off the Project Plan.

## Technical Requirements

### Files and Islands

- Pages, layouts and static sections are `.astro`. A `.tsx` file is right only for an interactive island — a whole compound component wrapped as one, or a `section-form` form.
- Only add `client:*` directives for real interactivity; every island ships JS.
- Prefer native JavaScript (`<script>` in `.astro`) for toggles, animations and simple validation. Reach for React only for complex state or React-only libraries.

### `className` on React Components

shadcn/React components take `className`; native HTML in `.astro` takes `class`. `<Button class="px-4">` fails `astro check` and `@astrojs/react` silently drops the `class` prop at render. Don't pass `style` to shadcn components either — use Tailwind utilities (`delay-100`, or custom delays in `@theme {}`).

### Compound Components

Radix-based components with sub-parts share React Context, so dropping the parts into `.astro` one by one makes each its own island and breaks (`<SelectValue> must be used within <Select>`). Affected: `Select`, `Tabs`, `Accordion`, `DropdownMenu`, `RadioGroup`, `Dialog`, `AlertDialog`, `Sheet`, `Popover`, `HoverCard`, `ContextMenu`, `Menubar`, `NavigationMenu`, `Command`, `Collapsible`, `ToggleGroup`, `Tooltip`.

Wrap the whole compound in one `.tsx` component and use it as a single island:

```tsx
// src/components/CountrySelect.tsx
import { Select, SelectTrigger, SelectValue, SelectContent, SelectItem } from "@/components/ui/select";

export function CountrySelect() {
  return (
    <Select>
      <SelectTrigger><SelectValue placeholder="Pick a country" /></SelectTrigger>
      <SelectContent><SelectItem value="si">Slovenia</SelectItem></SelectContent>
    </Select>
  );
}
```

```astro
<CountrySelect client:load />
```

For a simple single-value select in a form, a styled native `<select>` is better — no island, works without JS.

### Fonts

Invoke the `fonts` skill for any custom font. Fonts go through the Astro Fonts API (top-level `fonts` in `astro.config.mjs` on Astro 6+, `experimental.fonts` on 5.x) and the `<Font />` component — never `@import` or `@font-face` in CSS.

### Images

- Local raster images: `<Picture>` from `astro:assets` with `formats={['webp']}`, `width={W}` (the measured display width, not the file's size), `widths={[W, W * 2]}` and a measured `sizes` — `sizes` without `widths` emits no srcset at all.
- A `.webp` / `.avif` source also needs `fallbackFormat="webp"`, or the `<img>` fallback is transcoded to a large PNG. Omit it on `.jpg`/`.jpeg`/`.gif`/`.svg`.
- Pass `width` alone — adding a `height` that disagrees with the source ratio crops the file. Let CSS size the box (`w-full`); the `width` prop only sizes the file.
- Local SVG: import it and render `<img src={logo.src} width={logo.width} height={logo.height} alt="…">`.
- External placeholders (Unsplash): plain `<img>`. `loading="eager"` above the fold, `loading="lazy"` below.
- `hakuto-review` carries the full rules, the Astro internals behind them, and a symptom table.

**Never reference `/src/assets/...` as a string path in `src`.** Vite serves it in dev, but the path doesn't exist in the build, so the image 404s on the live site while looking fine locally. Import the asset instead (`import photo from "@/assets/photo.jpg"`). Files that need a stable public URL go in `public/` and are referenced as `/name.ext`. Before declaring a page done, grep it for `/src/assets` — expect zero matches.

### Tailwind CSS v4

- Delete `tailwind.config.mjs` if it exists — v4 ignores it.
- `src/index.css` order: `@import 'tailwindcss'` (must be first — `@import` after other rules is dropped), `@plugin 'tailwindcss-animate'`, `@theme { … }`, `@layer base { … }`.
- All custom tokens go in `src/index.css`.

### Code Hygiene

Remove unused imports and variables, and type callback parameters explicitly (e.g. Vite middleware `(_req: IncomingMessage, res: ServerResponse, next: () => void)`) — implicit `any` and dead code fail `bun run check`.

### Verification Before Completion

After a batch of edits to `.astro` / `.ts` / `.tsx` files, run `bun run check` once and either fix the **new** errors your edits introduced or surface them to the user in one line. Skip it for trivial copy or `index.css`-only edits. Don't "fix" pre-existing unrelated errors unless asked — call them out instead.

### Favicon

Favicon sources go in `src/assets/`, and the `astro-favicons` plugin in `astro.config.mjs` generates every format at build time. To change it, update the plugin's `input`, `name` and `short_name`. A favicon you find in `public/` gets copied into `src/assets/` first.

## Quality Standards

- Semantic HTML with a proper heading hierarchy, mobile-first, accessible, with real alt text.
- Tailwind utilities for all styling — no inline styles.
- Every `href="#features"` needs a matching `id="features"`.
- Internal links end in a slash: `href="/about/"`, never `href="/about"`. The site uses `trailingSlash: "always"`, so a slashless href costs a 301 (~750ms per hop on mobile). Grep for `href="/[a-z]` without a trailing slash before declaring a page done.
- Placeholder copy you write starts with `TODO:` so `prelaunch-checklist` finds it.

## SEO & Structured Data

Pass JSON-LD through Layout's `schema` prop (`src/components/Schema.astro` + `schema-dts`):

```astro
---
import type { WebSite, WithContext } from "schema-dts";
const websiteSchema: WithContext<WebSite> = {
  "@context": "https://schema.org",
  "@type": "WebSite",
  name: "My Site",
  url: Astro.url.origin,
};
---
<Layout title="Home" schema={websiteSchema}>…</Layout>
```

- Annotate with `WithContext<T>`, not `satisfies T` — bare schema-dts types have no `@context` property, so `satisfies` fails type-checking and doesn't match the prop type.
- JSON-LD must not be HTML-escaped: `<script type="application/ld+json">` is raw text, so `&apos;` reaches consumers literally. `Schema.astro` escapes only `<` on purpose — keep using it.
- Common types: WebSite, Organization, LocalBusiness, Product, Article, FAQPage, BreadcrumbList.

## Cloudflare & Deploy

### Environment Variables and Secrets

The site builds with `output: "static"` — every page is prerendered. **Runtime env exists only inside `worker/`.**

- **Never use `import.meta.env.*` under `src/`.** No `.env` file, CI var, Workers secret or `wrangler.toml` `[vars]` reaches it, so it is `undefined` in production.
- Prerendered config (site name, analytics domain, public URLs, feature flags): hardcode it in source, centralized in `src/lib/site.ts`.
- Runtime and secret values: read them from `env` in a worker handler, `handler(request, env, ctx)`.
- **Never put secrets in `src/`** — everything in the static build is public.

### Worker and `wrangler.toml`

`run_worker_first = ["/~*"]` sends `/~*` paths to `worker/index.js`; everything else is served from `dist/client/` by Cloudflare's asset layer, so the worker needs no `env.ASSETS` fallback. `not_found_handling = "404-page"` serves the prerendered `404.astro`. These rules apply under `bun run preview` and in production — **not** under `bun run dev`. Test any `/~/` route with `bun run preview`. Handler conventions are in `worker/README.md`.

### `public/` Rules

- **Site-wide `_headers` rules go under `/*`.** A rule scoped to `/` is an exact match for the homepage only and fails silently. Verify with `curl -sI <origin>/some/inner/page/`, never just `/`.
- `public/` and `src/pages/` share one URL namespace — `public/robots.txt` would collide with `src/pages/robots.txt.ts`.
- Security headers in `_headers` are tuned for the default marketing stack (GTM, Cookiebot, Plausible, FB Pixel, Paddle, Vimeo/YouTube); adding another third party or a feature like `camera` means updating the matching directive.

### Adapter

`astro.config.mjs` loads `@astrojs/cloudflare` with `imageService: "custom"` (the only value that keeps Astro's sharp service — `"compile"` and `"passthrough"` replace it) and `prerenderEnvironment: "node"`, and disables the adapter in development so dev images work. The comments there explain why; leave all three as they are.

## Troubleshooting

| Issue | Solution |
|---|---|
| TypeScript error on `class` | Use `className` on React/shadcn components |
| Styles not applying | `@import 'tailwindcss'` must be the first line of `index.css` |
| Images 404 in production but work in dev | Raw `/src/assets/...` path — import the asset |
| Huge PNGs next to webp variants in `dist/client/_astro/` | `.webp`/`.avif` source missing `fallbackFormat="webp"` |
| Images far larger than displayed, poor LCP | Missing `width` / `widths` / `sizes` on `<Picture>` |
| Images broken in dev or build | Adapter `imageService` changed from `"custom"`, or adapter enabled in dev |
| `/~/…` route 404s locally | You're on `bun run dev`; use `bun run preview` |
| Pagefind or WebMCP search unavailable in dev | Expected — the index exists only in a build. Check on `bun run preview` or a deploy |
| `import.meta.env.MY_VAR` is `undefined` in production | Hardcode it in `src/lib/site.ts`, or read it from `env` in the worker |
| Headers missing on every page but the homepage | `_headers` rule scoped to `/` instead of `/*` |
| JSON-LD contains `&apos;` / `&quot;` | Something HTML-escaped it — use `Schema.astro` |
| Large HTML, render delay dominates LCP | `build.inlineStylesheets` forced to `"always"` — keep `"auto"` |
| Build fails | Unused imports, implicit `any` |
| Build fails: "Failed to get static paths from Cloudflare prerender server (404)" | Restore `prerenderEnvironment: "node"` on the adapter |
| Every page's git-derived date is the deploy date | Cloudflare builds a shallow clone — set the dashboard build command to `git fetch --unshallow \|\| true && bun run build` |
| Sitemap / canonicals show `localhost:4321` | Set `site` in `astro.config.mjs` and redeploy |
| Anchor link does nothing | Target element is missing the matching `id` |
